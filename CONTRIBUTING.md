# Contributing to JARVIS

Спасибо за интерес к проекту JARVIS! Мы приветствуем вклад сообщества.

## Как внести вклад

### Сообщения об ошибках (Bug Reports)

1. Проверьте, что ошибка не была reported ранее в [Issues](https://github.com/msdrakula/J.A.R.V.I.S/issues)
2. Создайте новый issue с подробным описанием:
   - Версия JARVIS (`jarvis --version`)
   - Версия Go (`go version`)
   - Операционная система
   - Шаги для воспроизведения
   - Ожидаемое и фактическое поведение
   - Логи (если есть)

### Предложения улучшений (Feature Requests)

1. Создайте issue с меткой `enhancement`
2. Опишите проблему, которую решает ваше предложение
3. Предложите возможное решение (если есть)

### Pull Requests

1. Форкните репозиторий
2. Создайте ветку для вашей фичи (`git checkout -b feature/amazing-feature`)
3. Напишите код, следуя стилю проекта
4. Добавьте тесты для новой функциональности
5. Убедитесь, что все тесты проходят (`go test ./...`)
6. Закоммитьте изменения (`git commit -m 'Add amazing feature'`)
7. Запушьте в ветку (`git push origin feature/amazing-feature`)
8. Откройте Pull Request

### Стиль кода

- Используйте `gofmt` для форматирования
- Следуйте [Effective Go](https://golang.org/doc/effective_go.html)
- Добавляйте комментарии к экспортируемым функциям
- Используйте осмысленные имена переменных и функций

### Тесты

- Все новые функции должны быть покрыты юнит-тестами
- Используйте `testing` пакет стандартной библиотеки
- Для HTTP-тестов используйте `httptest`
- Для работы с БД в тестах используйте временные файлы

## Code of Conduct

Мы ожидаем уважительного отношения ко всем участникам проекта. Пожалуйста, будьте вежливы в обсуждениях и code review.

## Вопросы?

Если у вас есть вопросы, не стесняйтесь создавать issue с меткой `question`.
